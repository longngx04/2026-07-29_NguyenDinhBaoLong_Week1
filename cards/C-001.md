# C-001 — Pin and safely run the local WebGoat target

status: done
deps: none
implements: FR1

## Scope

Add WebGoat source as a submodule pinned to `v2025.3`, Docker Compose using the matching `webgoat/webgoat:v2025.3` image, and `make target-up`/`make target-down`. The target-up command waits for WebGoat's actuator health endpoint and the Compose port mappings must bind only to the loopback interface.

## Allowed files

- `.gitmodules`
- `targets/webgoat` (submodule gitlink only)
- `docker-compose.yml`
- `Makefile`
- `.gitignore`
- `cards/C-001.md`

## Verify (run these before calling the card done)

- [x] `git submodule status` prints the commit for WebGoat `v2025.3`.
- [x] `make target-up` exits 0 and prints the WebGoat URL.
- [x] `curl --fail --silent http://127.0.0.1:8080/WebGoat/actuator/health` returns JSON containing `"status":"UP"`.
- [x] `docker compose ps` shows only loopback host bindings for published WebGoat ports.
- [x] `make target-down` exits 0 and `docker compose ps` has no running WebGoat service.

## Done-evidence (world-state proof, named BEFORE building)

While the target is up, a local browser can open `http://127.0.0.1:8080/WebGoat/` and the documented actuator health URL returns HTTP 200 with status `UP`; its Docker ports are not reachable through non-loopback host bindings.
